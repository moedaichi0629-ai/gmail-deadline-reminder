# Google Sheets × Gmail 納期リマインド自動送信ツール 要件定義書

## 改訂履歴

| 版 | 内容 |
|---|---|
| 1.0 | 初版。翌日が納期の「未完了」案件に1回だけ通知する構成 |
| 2.0 | 通知タイミングの設定化（例：3日前・前日・当日の複数回通知）、完了扱いステータスの設定化、件名・本文のテンプレート化、送信履歴シートの追加、通知タイミングごとの二重送信防止に対応 |

## 1. Overview

Googleスプレッドシートで管理している案件の納期を毎日自動確認し、設定した通知タイミング（例：納期の3日前・前日・当日）に該当する未完了案件について、担当者へGmailでリマインドメールを自動送信する。送信結果は送信履歴シートに記録する。

## 2. Background

現在は担当者がスプレッドシートを毎日確認し、納期が近い案件を確認したうえで、各担当者へ手動で連絡している。

この定型作業を自動化し、日々の確認・連絡作業の負担軽減とリマインド漏れの防止を目的とする。

## 3. Goal

以下の業務を自動化する。

1. 毎日スプレッドシートを確認する
2. 納期までの残り日数が通知タイミング（例：3日前・前日・当日）に該当する案件を抽出する
3. 「完了」扱いのステータス以外の案件だけを対象にする
4. 担当者へリマインドメールを送信する
5. 送信結果（成功・失敗）を送信履歴シートに記録する
6. 同じ案件・同じ通知タイミングのメールを重複して送信しない

通常運用では、利用者が通知処理を手動操作する必要がない状態を目指す。

### 管理者

対象Googleスプレッドシートを管理するGoogleアカウント。

### メール受信者

各案件の「担当者」に設定されたメールアドレス。

## 5. Spreadsheet

### 案件管理シート

シート名：案件管理

| 列名      | 用途                |
| ------- | ----------------- |
| 案件名     | 案件の名称             |
| 担当者     | 担当者名              |
| メールアドレス | リマインドメール送信先       |
| 納期      | 案件の納期             |
| ステータス   | 案件の進行状態（例：未対応・対応中・完了） |
| 最終通知日   | 最後にリマインドメールを送信した日 |

「最終通知日」はシステム管理用の列とし、通常業務では利用者が操作する必要はない。

### 送信履歴シート

シート名：送信履歴（初回実行時に自動作成する）

| 列名 | 用途 |
|---|---|
| 送信日時 | メール送信処理を行った日時 |
| 案件名 | 対象案件の名称 |
| 担当者 | 担当者名 |
| 送信先 | 送信先メールアドレス |
| 納期 | 対象案件の納期 |
| 通知タイミング | 3日前・前日・当日など |
| 件名 | 送信したメールの件名 |
| 結果 | 送信成功 / 送信失敗 |
| エラー内容 | 送信失敗時の理由 |
| 通知キー | 二重送信防止の判定に使用するシステム管理用の値 |

### データ量

* シート全体：100〜200件程度
* 新規追加：1日5〜10件程度

### 納期形式

Googleスプレッドシート上の日付として管理する。

表示例：

2026/09/20

## 6. Reminder Conditions

以下の条件をすべて満たした行をリマインド対象とする。

1. 納期が日付として正しい
2. ステータスが「完了」扱いのステータス（設定値。初期値は「完了」）ではない
3. 実行日から納期までの残り日数が、通知タイミング（設定値。初期値は3日前・前日・当日）のいずれかと一致する
4. 同じ案件・同じ納期・同じ通知タイミングのメールがまだ送信成功していない

条件イメージ：

残り日数 IN 通知タイミング（例：3, 1, 0）
AND
ステータス NOT IN 完了扱いのステータス（例：完了）
AND
同じ通知が未送信

各行を1案件として扱う。

## 7. Email

### 送信元

対象スプレッドシートを管理しているGoogleアカウントから送信する。

### 送信先

各行の「メールアドレス」。

### 件名・本文

テンプレートとして設定値で管理し、以下の項目を差し込めるようにする。

* {案件名}
* {担当者}
* {納期}（yyyy/MM/dd形式）
* {残り日数}（数値）
* {期限}（「本日」「明日」「3日後」のような表記）

初期値の件名：

【納期リマインド】{案件名}の納期は{期限}（{納期}）です

初期値の本文：

{担当者}さん、案件名・納期・期限を記載し、進捗の確認を依頼する文面

## 8. Automatic Execution

Google Apps Scriptの時間主導トリガーを使用して毎日自動実行する。

実行時間：

毎朝9時頃

土日・祝日も通常どおり実行する。

## 9. Duplicate Prevention

同じ案件について、同じ通知タイミングのリマインドメールを複数回送信しない。

* 送信履歴シートに「送信成功」として記録された通知キー（案件名・送信先・納期・通知タイミングの組み合わせ）を確認し、同じ通知キーのメールは送信しない
* 通知タイミングが異なれば、同じ案件でも送信する（例：3日前通知を送信済みでも、前日通知は送信する）
* 送信に失敗した通知は「送信失敗」として記録し、二重送信防止の対象にはしない（同じ日の再実行で再送できる）
* 納期が変更された場合は別の通知として扱う
* メール送信が正常に完了した場合は「最終通知日」を当日に更新する

ほぼ同時に複数処理が起動するケースについては、LockServiceにより同時実行を防止する。

## 10. Error Handling

以下のケースを考慮する。

* 案件データが0件
* 必須ヘッダーが存在しない
* 納期が空欄
* メールアドレスが空欄
* 担当者が空欄
* 案件名が空欄
* Gmail送信に失敗
* 想定外のデータが入力されている

1件の不正データによって、可能な限り他の正常な案件まで処理できなくならないようにする。

Gmail送信の失敗は送信履歴シートに記録する。その他のエラー・スキップはApps Scriptの実行ログから原因を確認できるようにする。

## 11. Security

APIキー、トークン、パスワード等をソースコードへ直接記載しない。

今回の基本構成では外部APIは使用しない。

Google SheetsおよびGmailへのアクセスはGoogle Apps Scriptの権限を利用する。

不要な外部サービスは追加しない。

## 12. Out of Scope

今回の開発には以下を含めない。

* LINE通知
* Slack通知
* 専用Web管理画面
* AIによるメール文章生成
* 案件ごとに異なる通知タイミングの設定（通知タイミングは全案件共通）
* 実行されなかった日の通知の後追い送信
* 分析ダッシュボード
* 案件ID管理システム

## 13. Future

必要になった場合、以下の拡張を検討できる。

* LINE / Slack通知
* 案件ごとの通知タイミング設定
* 管理画面
* 案件IDによる管理
* 管理者へのエラー通知

これらは今回の実装には含めない。

## 14. Implementation Phases

### Phase 1：シート・基盤準備

* 「案件管理」シート取得
* ヘッダー取得
* 各列の特定
* 案件データ取得
* 元の行番号保持
* 基本的な入力チェック

### Phase 2：条件判定・メール送信

* 翌日納期判定
* 未完了判定
* Gmail送信
* 最終通知日更新

### Phase 3：重複防止・自動実行

* 同日重複送信防止
* 同時実行対策
* 毎日9時頃の時間主導トリガー
* 基本的なエラーログ

### Phase 4：統合テスト・納品準備

* 正常系テスト
* 異常系テスト
* 重複送信テスト
* 自動実行確認
* 納品準備

### Phase 5：通知タイミング・履歴の拡張（2.0）

* 通知タイミングの設定化と複数回通知
* 完了扱いステータスの設定化
* 件名・本文のテンプレート化
* 送信履歴シートへの記録
* 通知タイミングごとの二重送信防止
* Node.js（node:test）によるロジックの自動テスト

一度にすべてのPhaseを実装せず、

実装 → 動作確認 → テスト → 次のPhase

の順序で進める。

## 15. Acceptance Criteria

以下をすべて満たした場合に完成とする。

* Googleスプレッドシートから案件情報を取得できる
* 毎日9時頃に自動実行される
* 土日・祝日も実行される
* 残り日数が通知タイミング（初期値：3日前・前日・当日）に該当する案件だけが通知対象になる
* 「完了」扱いのステータスの案件には送信されない
* 「完了」扱い以外のステータス（未対応・対応中など）の案件は通知対象になる
* 指定された担当者メールアドレスへ送信される
* テンプレートに沿った件名・本文が使用され、案件名・担当者・納期・期限が差し込まれる
* 送信結果（成功・失敗）が送信履歴シートに記録される
* メール送信成功後に最終通知日が更新される
* 同じ案件・同じ通知タイミングのメールが重複送信されない
* 通知タイミングが異なれば、同じ案件にも送信される
* 処理が複数回実行された場合でも重複送信を防止できる
* 最終通知日・送信履歴は通常業務で手動操作する必要がない
* 不正なデータが存在した場合、可能な限り他の正常案件の処理を継続できる
* 基本的なエラー内容を実行ログ・送信履歴から確認できる

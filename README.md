# Googleスプレッドシート × Gmail 納期リマインド自動送信ツール

スプレッドシートで管理している案件の納期を毎日自動でチェックし、納期の3日前・前日・当日などに担当者へGmailでリマインドメールを自動送信して、送信結果を履歴シートに記録するツールです（Google Sheets / Google Apps Script / Gmail）。

[作品一覧](https://github.com/moedaichi0629-ai/landing-page) · [ポートフォリオ](https://moedaichi0629-ai.github.io/)

> **このリポジトリについて**
> 受託開発を想定して制作した**ポートフォリオ用の模擬案件（デモ）**です。実在のクライアント・実案件ではなく、「スプレッドシートで案件と納期を管理している小規模チーム」を想定し、要件定義から実装・テストまでを一貫して行いました。リポジトリ内のサンプルデータはすべて架空のものです。

## 作業前 → 作業後

| | 作業前（想定） | 作業後 |
|---|---|---|
| 納期の確認 | 毎朝スプレッドシートを見て、納期が近い案件を探す | 毎日9時頃に自動でチェック |
| 担当者への連絡 | 案件ごとに手作業でメールを作成・送信 | 3日前・前日・当日に自動でリマインドメールを送信 |
| 連絡漏れ・重複 | 忙しい日は連絡漏れ、同じ連絡を二重に送ることも | 通知タイミングごとに1回だけ確実に送信 |
| 連絡したかの確認 | 記憶やメモに頼る | 送信日時・宛先・成功／失敗を送信履歴シートで確認 |

## 主な機能

- **毎日の自動チェック**：毎朝9時頃に自動実行（土日・祝日も実行）
- **複数タイミングでのリマインド**：初期設定は「3日前・前日・当日」。`REMINDER_DAYS = [3, 1, 0]` を書き換えるだけで変更可能
- **完了案件は自動で除外**：「完了」以外のステータス（未対応・対応中など）の案件だけに通知。完了扱いにするステータスも設定で追加可能
- **件名・本文のテンプレート**：`{案件名}` `{担当者}` `{納期}` `{期限}` `{残り日数}` を差し込み、文面は設定で変更可能
- **送信履歴の記録**：送信日時・案件・通知タイミング・送信成功／失敗・エラー内容を「送信履歴」シートに自動記録
- **二重送信の防止**：同じ案件・同じ通知タイミングのメールは1回だけ。3日前通知を送った案件にも、前日・当日の通知は届く
- **同時実行の防止**：処理が同時に起動しても重複送信しない（LockService）

### 送信されるメールの例（初期設定・3日前通知）

```
件名: 【納期リマインド】コーポレートサイト制作の納期は3日後（2026/10/08）です

山田さん

お疲れさまです。納期が近づいている案件のお知らせです。

■ 案件名：コーポレートサイト制作
■ 納期　：2026/10/08（3日後）

進捗をご確認のうえ、ご対応をお願いいたします。

※このメールは「案件管理」シートの情報をもとに自動送信しています。
```

前日通知では「納期は明日」、当日通知では「納期は本日」と表示されます。

## 処理の流れ

```
案件管理シート（案件名・担当者・メールアドレス・納期・ステータス）
   ↓
時間主導トリガー（毎日9時頃）
   ↓
Google Apps Script
   ├─ 納期までの残り日数を計算
   ├─ 通知タイミング（3日前・前日・当日）に該当するか判定
   ├─ 完了案件・送信済みの通知を除外
   ├─ テンプレートから件名・本文を作成
   └─ Gmailでリマインドメールを送信
   ↓
送信履歴シートに結果を記録（送信成功／送信失敗）
＋ 案件管理シートの「最終通知日」を更新
```

## 使用技術

- Google Sheets
- Google Apps Script（JavaScript）
- Gmail
- Node.js（ロジックの自動テスト用途のみ。本番機能では使用していません）

外部API・外部サーバー・有料サービスは使用していません。APIキー等の秘密情報も不要です（Googleアカウントの権限承認のみで動作します）。

## セットアップ

1. Googleスプレッドシートを作成し、シート名を「案件管理」にする
2. 1行目に以下のヘッダーを入力する（列の順番は自由。ほかの列があっても動作します）

   | 案件名 | 担当者 | メールアドレス | 納期 | ステータス | 最終通知日 |
   |---|---|---|---|---|---|
   | コーポレートサイト制作 | 山田 | demo-yamada@example.com | 2026/10/08 | 対応中 | |
   | LP制作 | 佐藤 | demo-sato@example.com | 2026/10/06 | 未対応 | |
   | 採用サイト制作 | 高橋 | demo-takahashi@example.com | 2026/10/06 | 完了 | |

   ※上記は架空のサンプルです。「最終通知日」は空欄のままにしておけば、送信時に自動で記録されます。
3. 「拡張機能」→「Apps Script」を開き、`Code.gs` の内容を貼り付けて保存する
4. スプレッドシートとApps Scriptのタイムゾーンを「Asia/Tokyo」に設定する（ファイル → 設定／プロジェクトの設定）
5. Apps Scriptエディタで `setupDailyTrigger` を1回実行し、毎日9時頃の自動実行を設定する（初回は権限の承認画面が表示されます）

「送信履歴」シートは初回の送信処理で自動作成されます。

## 使い方

- **通常運用**：案件管理シートに案件を追加・更新するだけです。毎日自動で判定・送信・記録されます。
- **完了した案件**：ステータスを「完了」にすると、それ以降はリマインドが送られません。
- **送信結果の確認**：「送信履歴」シートで、いつ・どの案件に・どのタイミングの通知を送ったか、成功／失敗を確認できます。
- **すぐに実行したい場合**：Apps Scriptエディタで `sendDeadlineReminders` を実行します（送信済みの通知は再送されません）。
- **自動実行を止めたい場合**：`removeDailyTrigger` を実行します。

### 設定の変更

`Code.gs` 冒頭の「設定」ブロックを書き換えます。

| 設定 | 初期値 | 内容 |
|---|---|---|
| `REMINDER_DAYS` | `[3, 1, 0]` | 通知タイミング（納期の何日前か。0は当日） |
| `COMPLETED_STATUSES` | `['完了']` | 通知しないステータス |
| `EMAIL_SUBJECT_TEMPLATE` | 上記メール例の件名 | 件名のテンプレート |
| `EMAIL_BODY_TEMPLATE` | 上記メール例の本文 | 本文のテンプレート |
| `REMINDER_TRIGGER_HOUR` | `9` | 自動実行の時刻（時） |

## 技術詳細・注意事項

<details>
<summary>通知の判定条件</summary>

以下をすべて満たす案件に送信します。

1. 納期が日付として正しい（スプレッドシートの日付、または `yyyy/MM/dd`・`yyyy-MM-dd` 形式の文字列）
2. ステータスが `COMPLETED_STATUSES` に含まれない
3. 実行日から納期までの残り日数が `REMINDER_DAYS` のいずれかと一致する
4. 同じ通知キー（案件名・送信先・納期・通知タイミング）が送信履歴に「送信成功」として記録されていない

日数は時刻を無視した年月日単位で計算します（スプレッドシートのタイムゾーン基準）。

</details>

<details>
<summary>送信履歴シートの列構成</summary>

| 列 | 内容 |
|---|---|
| 送信日時 | 送信処理を行った日時 |
| 案件名 | 対象案件 |
| 担当者 | 担当者名 |
| 送信先 | 送信先メールアドレス |
| 納期 | 対象案件の納期 |
| 通知タイミング | 3日前・前日・当日など |
| 件名 | 送信したメールの件名 |
| 結果 | 送信成功 / 送信失敗 |
| エラー内容 | 送信失敗時の理由 |
| 通知キー | 二重送信防止の判定に使用するシステム管理用の値 |

「送信成功」の行が二重送信防止の判定に使われるため、送信履歴シートの行は削除しないでください。

</details>

<details>
<summary>エラー時の動作</summary>

| ケース | 動作 |
|---|---|
| Gmail送信の失敗 | 送信履歴に「送信失敗」とエラー内容を記録。他の案件の処理は継続。同じ日に再実行すると再送される |
| 案件名・担当者・メールアドレスが空欄 | 送信せずスキップし、実行ログに理由を出力 |
| 納期が空欄・不正 | 対象外として実行ログに理由を出力 |
| 必須ヘッダーが不足 | 処理を中止し、不足しているヘッダー名をエラーとして出力 |
| 処理の同時起動 | 後から起動した処理はロックを取得できず、何も送信せずに終了 |

</details>

<details>
<summary>注意事項・スコープ外</summary>

- 通知タイミングは全案件共通です（案件ごとに異なるタイミングは設定できません）。
- 自動実行が行われなかった日の通知は、後日まとめて送信しません（その日の残り日数に該当する通知のみ送信します）。
- メールは、スクリプトを実行・承認したGoogleアカウントから送信されます。Gmailの1日あたりの送信数上限が適用されます。
- 納期を変更した場合は別の通知として扱い、新しい納期に対して改めて通知します。
- 以下は今回実装していません：LINE／Slack通知、専用Web管理画面、AIによる文章生成、管理者へのエラー通知、分析ダッシュボード。

</details>
